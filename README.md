# Chronosphere

Кабинет репетитора по истории. Репетитор ведёт каталог тестов, источников и PDF. В кабинете родителя представитель управляет согласием для подтверждённой связи с учеником. Ученик получает доступ к учебному разделу после согласия действующей версии.

## Локальный запуск

Нужны Docker с Compose v2 и свободные локальные порты 3000, 5432 и 9000. Скопируйте `.env.example` в `.env` и выполните команды из корня проекта.

```powershell
Copy-Item .env.example .env
docker compose up --build -d
docker compose exec web npm run db:seed
docker compose ps -a
```

Откройте [http://localhost:3000](http://localhost:3000). Пароль для вымышленных аккаунтов берётся из `PILOT_PASSWORD` при первом создании. После смены значения используйте команду сброса для существующих аккаунтов.

| Роль | Почта |
|---|---|
| Репетитор | `tutor@example.test` |
| Ученик | `student@example.test` |
| Родитель | `parent@example.test` |
| Технический репетитор для проверки доступа | `tutor2@example.test` |

Compose применяет миграции и создаёт закрытый бакет до запуска приложения и обработчика. В состоянии `Exited (0)` у `migrate` и `storage-init` команды завершились успешно. Для диагностики выполните `docker compose logs web worker migrate storage-init`. Перезапуск сохраняет данные в томах Compose.

### Запуск для разработки

Нужны Node.js 22.13+ и npm. При локальном запуске URL базы и S3 берутся из `.env`. Команды в PowerShell выполняются как `npm.cmd`, если политика системы блокирует `npm.ps1`.

```text
docker compose up -d postgres storage storage-init
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

В отдельном терминале запустите `npm run worker`. Если PostgreSQL и S3 доступны отдельно, можно указать их адреса в `.env` и выполнить команды npm. Бакет должен быть создан заранее. Переменные хостовой конфигурации см. в `.env.example`.

## Работа в кабинетах

- В «Тестах» создайте черновик, добавьте вопросы, расставьте их и выберите классификацию. Подтверждение требует хотя бы одного вопроса, заполненной классификации и ровно одного правильного ответа среди двух или более разных вариантов. Сохранение черновика после правки снимает отметку проверки.
- В «Источниках» вставьте текст или загрузите TXT в UTF-8. Откройте сохранённый текст, подтвердите просмотр и запросите черновик. В каталоге тестов виден статус задания. В редакторе рядом с вопросом видна цитата и ссылка на источник. Проверьте формулировки, ответы и исторические даты.
- В «Презентациях» подтвердите просмотр плана и отправьте его в Gamma. Обработчик продолжает работу после закрытия вкладки. В каталоге скачивается сохранённый PDF. Ручная загрузка PDF до 20 МБ доступна из того же раздела.
- Для сценария согласия войдите как родитель, прочитайте демонстрационный документ и предоставьте согласие. Войдите как ученик и откройте учебный раздел. После отзыва представителем или публикации новой версии ученику снова потребуется подтверждение.

## Оператор

Публичная регистрация закрыта. Команды ниже выполняются на машине, у которой есть доступ к базе. Для Compose добавьте перед `npm` префикс `docker compose exec web`. Для `create` и `reset` передайте пароль через переменную `OPERATOR_PASSWORD` (в Compose можно передать её через `docker compose exec -e OPERATOR_PASSWORD web …`). Пароль требуется длиной от 12 до 128 символов.

```text
npm run account -- create tutor3@example.test TUTOR "Новый репетитор"
npm run account -- reset tutor3@example.test
npm run account -- revoke tutor3@example.test
npm run account -- link parent@example.test student@example.test
npm run account -- consent-version pilot-2 path/to/consent.txt
```

Сброс пароля отзывает все существующие сессии. Команда активации согласия принимает UTF-8 TXT и сохраняет новую версию, деактивируя предыдущую. Связь семьи создаёт оператор для вымышленных аккаунтов.

## Провайдеры и тестовый стенд

- По умолчанию `AI_PROVIDER=mock`. Для реальной генерации задайте `AI_PROVIDER=yandex`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` и при необходимости `YANDEX_MODEL`. Адаптер использует структурированный ответ. Сервер сверяет схему, справочники и наличие цитаты в оригинале. [Документация Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-structured)
- Для Gamma задайте `GAMMA_API_KEY`. Задание отправляется с экспортом в PDF. После записи ID обработчик может возобновить опрос или скачивание. Если подтверждение отправки потеряно, задание покажет ошибку. Историю и списания можно сверить в Gamma. При успешной генерации кабинет показывает число списанных кредитов, если Gamma вернула его. [Документация Gamma](https://developers.gamma.app/guides)
- Для отдельного тестового стенда задайте `PILOT_DOMAIN` и `BETTER_AUTH_URL=https://ваш-домен`, сгенерируйте отдельный секрет с помощью `openssl rand -base64 32` и задайте новые пароли. Направьте DNS на стенд, откройте 80 и 443, затем выполните `docker compose --profile https up --build -d`. Caddy получает сертификат и проксирует запросы к приложению. Для сценария размещения в РФ подготовьте приложение, БД, хранилище и резервные копии в РФ.
- На целевом стенде выполните по одному сквозному запросу к Gamma и Yandex AI Studio на вымышленных учебных данных. Запишите доступность ключа, пригодность результата, время и расход. Для двух уроков сравните время с привычным процессом и посчитайте исправления в вопросах. Для реальных семей в плане предусмотрено отдельное согласование с юристом.

## Проверки

```text
npm run check
npm test
npm run build
npm run test:smoke
```

Последнюю команду запускайте на хосте после старта приложения и создания тестовых аккаунтов. Она использует `BETTER_AUTH_URL` и `PILOT_PASSWORD` из `.env`.

Проверьте также чужие прямые ссылки на тест и PDF, загрузку TXT, удаление и перестановку вопросов, отзыв согласия, повтор запроса генерации и скачивание обоих PDF после `docker compose restart web worker`.

### Резервное копирование и восстановление

На тестовом стенде остановите запись в приложение на время копирования БД и PDF. Храните снимок PostgreSQL и копию закрытого бакета вместе. Для выгрузки PostgreSQL, в том числе из PowerShell:

```text
docker compose stop web worker
docker compose exec -T postgres pg_dump -U history -d history -Fc -f /tmp/history.dump
docker compose cp postgres:/tmp/history.dump ./history.dump
docker compose start web worker
```

Перед `start` скопируйте содержимое бакета в закрытое резервное хранилище, например через `mc mirror source/history-pdfs backup/history-pdfs` с настроенными псевдонимами. Для проверки восстановления разверните отдельную чистую БД и бакет, скопируйте дамп в контейнер и выполните `pg_restore -U history -d history -Fc /tmp/history.dump`. Восстановите PDF с исходными ключами объектов, запустите приложение с адресами восстановленных сервисов и проверьте вход, согласие, тест и скачивание PDF.
